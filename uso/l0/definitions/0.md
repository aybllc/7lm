# Definitions

This directory holds the controlled definitions list for the whole scaffold. Every entry is indexed
by source, version, context, and scope, so that the same word carrying different meanings in
different places stays legible. Competing definitions are PRESERVED as separate rows and are never
merged into one universal meaning; a single meaning governs only where an explicit adjudication has
named the scope it governs. Layer-local term tables in uso/l1–uso/l3 hold terms controlling only
inside their own layer; a term becomes a row here as soon as a second layer or L7 uses it. A term
controlling across more than one layer but absent from this list is a defect to fix.

## Manual work

1. Add or revise an entry in the SAME pass that introduces or changes a controlling technical use of
   a term. Do not defer glossary work to a later cleanup pass.
2. For each entry record four things: the source, the source version, the context the meaning was
   issued in, and the scope it applies to. If one of the four is unknown, write "unknown" rather
   than supplying a plausible value.
3. When two sources give a term different meanings, keep both as separate source-scoped rows keyed
   to their own sources. Do not force one universal definition and do not average the two.
4. Designate a CONTROLLING USE only by explicit adjudication, and only for a NAMED scope. State the
   scope in the same sentence as the designation.
5. Record the adjudication itself: what was decided, for which scope, on what date, by whom, and
   which meanings were not selected. Never silently edit or delete the meaning that lost.
6. Treat a new entry as provisional until adjudicated. A provisional entry may be used, provided the
   user names it as provisional at the point of use.
7. Skip this list for pure spelling correction, formatting, and ordinary connective prose. Those are
   lexical changes and need no glossary entry.
8. When a higher layer uses a definition owned here, make the higher layer NAME the row it uses
   rather than restate the wording in its own words.
9. Before committing a row, check the Basis column: exactly one value, and "Adapted from" only for a
   source actually read in that pass.

## Boundary

- A term is not a concept. One term may express several concepts, and one concept may be expressed
  by several terms. Never treat a shared spelling as a shared meaning.
- terminology, vocabulary, controlled vocabulary, taxonomy, thesaurus, and ontology are NOT
  interchangeable. Do not substitute one for another when describing an artifact.
- Syntax and semantics are distinct. A well-formed statement is not thereby a meaningful or true
  one, and a fixed grammar does not fix an interpretation.
- Semantic mapping is not identity. A recorded correspondence supports lookup and review; it does
  not make two things the same thing.
- synonymy, quasi-synonymy, equivalence, broader-term, narrower-term, related-term, similarity,
  mapping, and identity are DIFFERENT relations. Record which one you mean; do not collapse them.
- Similarity measurement and automatically inferred relations may prioritize human review, but they
  cannot create semantic authority and cannot stand in for adjudication.
- A claim carries an EPISTEMIC STATUS; a definition carries a DEFINITION STATUS. These are separate
  axes and a settled definition never implies a supported claim.
- canonical means owner-designated as controlling for a stated scope and version. It does NOT mean
  independently proven, validated, or universally true.
- A federation preserves independently maintained authorities and can retain inconsistencies between
  them; retained inconsistency is a recorded state, not a defect to be quietly fixed.
- A thesaurus union reconciles sources into a new combined vocabulary and therefore CREATES A NEW
  AUTHORITY ARTIFACT, with its own owner, scope, and version.
- Applying federation beyond thesauri, for example to layers, repositories, or pinned authorities,
  is a Project analogy and must be labelled as such wherever it is used.
- Harmonization is never automatic here and is never implied by pinning, mapping, or co-location.
- A unit symbol used anywhere in the corpus is a controlling term and gets its own row here, naming
  the issuing authority's binding in /L7/PINNED and stating the scale type; a layer may report a
  value in a unit, but no layer defines one outside this list.
- A **pinned** authority's content belongs to its owning repository and is never copied, paraphrased,
  or routed down from /L7/PINNED. A vocabulary source read directly and cited with its exact locator
  may be quoted or adapted, with the locator shown.

## Controlled definitions

Basis entries use short source designations; the full printed designations are in "Sources consulted
this pass" below.

| Term | Working meaning | Basis |
|---|---|---|
| agnostic | Committed to structure and handling rather than to any particular theory, tool, vendor, or domain, so material can be held without being endorsed. | Project working use |
| USO | The local seven-layer corpus at uso/l0 through uso/l6; the term operationally names that corpus, and expansion of the acronym remains author-controlled and is not inferred here. | Project rule |
| layer | One numbered band of the corpus, L0 through L6, fixing what kind of statement may be owned there and what it must name from below. | Project rule |
| Scientific Desktop | The L7 working surface outside the USO where intake, pinned authority bindings, compositions, and process lessons are handled before anything is routed into a layer. | Project rule |
| artifact | A concrete, referenceable object in this repository or in an owning repository; one thing can correspond to several artifacts under different roles or contexts. | Project working use |
| claim | A true-or-false statement about limitations on the values of an unambiguously defined property under stated conditions, always carrying an epistemic status. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| authority artifact | An artifact an owner designates as controlling for a stated scope and version, which consumers may bind to but never rewrite in place. | Project rule |
| semantic authority | The standing to fix what a term or definition means for a stated scope; held by an owner, and never acquired by a consumer through use, mapping, similarity, or custody. | Project rule |
| owner | The agent or repository bearing responsibility for an artifact's existence and content, and therefore the only party that can correct it. | Adapted from PROV-DM (W3C Recommendation 30 April 2013) |
| consumer | Any layer, composition, or repository that uses an artifact it does not own and must therefore name it rather than restate or repair it. | Project rule |
| scope | The stated extent within which a definition, claim, or designation applies; a definition suitable for general application may need a more specific one for a restricted application. | Adapted from ISO/IEC/IEEE 24765:2017(E), Clause 1.1 |
| term | A linguistic construct that refers to an entity; the sign used, not the meaning carried. | Adapted from ISO/IEC 2382:2015 |
| label | A short tag attached to an entry to record its status or handling; a label is not a definition and carries no semantic authority. | Project working use |
| lexical change | A change to wording, spelling, or formatting that does not alter a controlling technical use, and therefore requires no entry in this list. | Project rule |
| concept | The abstract unit of meaning that determines category membership, distinct from any term used to express it. | Adapted from ISO/IEC 2382:2015 |
| definition | A statement fixing the essential delimiting characteristics of a concept, such that the term can be replaced by it without introducing contradiction or circularity. | Adapted from JCGM 200:2012 (VIM) |
| source-scoped meaning | A meaning that holds only within the source, version, and context that issued it, recorded as its own row and never merged with a competing meaning. | Project rule |
| controlling use | The meaning designated to govern a NAMED scope after explicit adjudication; outside that scope other recorded meanings remain live. | Project rule |
| canonical | Owner-designated as controlling for a stated scope and version; it does not mean proven, validated, or universally true. | Project rule |
| interpretation | An assignment of meaning to a formal or textual structure; formal consistency under one interpretation does not select that interpretation. | Project rule |
| definition status | The axis recording how settled a definition is, such as provisional, source-scoped, adjudicated controlling, or superseded; separate from any claim's epistemic status. | Project rule |
| terminology | The set of designations used in a subject field together with the practice of establishing and maintaining them; no source read this pass defines it, so this is the scaffold's working use. | Project working use |
| vocabulary | A terminological dictionary containing designations and definitions from one or more specific subject fields. | Adapted from JCGM 200:2012 (VIM), quoting ISO 1087-1:2000, 3.7.2 |
| controlled vocabulary | A vocabulary restricted to an agreed set of terms, so that statements governed by it may use only those terms; no source read this pass defines it, so this is the scaffold's working use. | Project working use |
| taxonomy | A scheme that partitions a body of knowledge into classes and defines the relationships among the pieces. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| thesaurus | A structured vocabulary that records relations between terms such as synonymy, broader, narrower, and related; no source read this pass defines it, so this is the scaffold's working use. | Project working use |
| ontology | The logical structure of the terms used to describe a domain of knowledge, including both the definitions of the applicable terms and their relationships. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| type | A predicate characterizing a collection of things; asserting a type is a membership claim, not a warrant for the content typed. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| syntax | The structural components of a language and the rules defining how its constructs may be assembled into sentences. | Adapted from ISO/IEC/IEEE 31320-2:2012(E) |
| semantics | The meaning of the syntactic components of a language, fixed separately from the rules that make a statement well-formed. | Adapted from ISO/IEC/IEEE 31320-2:2012(E) |
| semantic mapping | A schema of metadata labels applied to data so it can be introduced into a corpus, that sense adapted from IEEE Std 2755-2017, 2.3; that it records correspondence only and establishes no identity is this scaffold's own rule, not the standard's. | Adapted from IEEE Std 2755-2017 |
| identity | (as a relation, the sense the Basis anchors) a recorded assertion that two names denote the same thing, so substitution is safe throughout a stated scope; this is the scaffold's own rule and no source read this pass supports the name-to-name direction. (Of an instance) the inherent property that distinguishes an instance from all other instances, independent of its property values or the classes it belongs to, that sense adapted from ISO/IEC/IEEE 31320-2:2012(E). | Project rule |
| equivalence | A recorded relation asserting that two expressions present aspects of the same thing within a named scope; it does not make them one entity. | Adapted from PROV-DM (W3C Recommendation 30 April 2013) |
| synonym | A term recorded as interchangeable with another within a stated scope, where the interchangeability is asserted by a person and not inferred by a tool. | Project working use |
| quasi-synonym | A term recorded as close to another but not interchangeable, kept as its own row so the difference is not lost. | Project working use |
| broader term | A term recorded as covering a wider extent than another within a stated vocabulary. | Project working use |
| narrower term | A term recorded as covering a narrower extent than another within a stated vocabulary. | Project working use |
| related term | A term cross-referenced as connected to another without being its synonym, its broader term, or its narrower term; no source read this pass fixes that three-way distinction, so this is the scaffold's working use. | Project working use |
| epistemic status | The axis recording how well a claim is supported by evidence appropriate to its type, separate from how settled its definitions are. | Project rule |
| scientific validity | Support for a claim by independent evidence adequate to the claim type; repository custody, an exact hash, authority, internal consistency, and provenance do not supply it. | Project rule |
| integrity | The degree to which a system, product, or component prevents unauthorized access to or modification of programs or data; a custody property, not a truth property. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| validation | Confirmation through objective evidence that the requirements for a specific intended use or application have been fulfilled, as distinct from verification that specified requirements have been met. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| contradiction | Two statements that cannot both hold under the same interpretation and the same scope. | Project rule |
| tension | A pull between statements that may each be defensible under differing scopes or interpretations; recorded as such rather than resolved by fiat. | Project rule |
| inconsistency | A set of statements that cannot be jointly satisfied under a stated interpretation; a property of the set, not a verdict on any single member. | Project rule |
| adjudication | The explicit act of deciding, for a named scope, which recorded meaning or which owner controls, with the decision and the non-selected alternatives written down. | Project rule |
| ratification | The recorded acceptance that an adjudicated decision now stands for the named scope; it fixes status, not truth. | Project rule |
| provisional | Admitted and recorded but not yet adjudicated; a provisional object may bear on several artifacts and may have several candidate owners. | Project rule |
| live alternative | A recorded meaning, method, or artifact that remains current even though a composition did not select it; non-selection never sends it to L6 history. | Project rule |
| candidate owner | A layer or repository that might own an artifact once its meaning, scope, and owner are clear; candidacy is not ownership and not routing. | Project rule |
| layer owner | The lowest layer able to state a local artifact without importing unresolved assumptions from a higher layer. | Project rule |
| routing | Moving an adjudicated local artifact from L7 intake to its owning layer, done only after its current meaning, scope, and owner are sufficiently clear. | Project rule |
| pin | A recorded exact binding in L7 to one specific version of an external authority artifact, holding the reference without copying the content. | Project rule |
| pinned authority | An external authority currently bound by a pin; several may be active at once, and pinning one neither ranks, merges, invalidates, nor supersedes another. | Project rule |
| fixed referent | The specific thing a binding points at, held constant by its fixed aspects so a later reference still lands on the same thing. | Adapted from PROV-DM (W3C Recommendation 30 April 2013) |
| immutable binding | A binding recorded so that it is never edited in place; a change means admitting a new binding and preserving the earlier one plus the successor relation. | Project rule |
| composition | An L7 assembly that uses named artifacts from several owners for a stated purpose; its choices are local to it and are never universal supersession. | Project rule |
| provenance | A record describing the people, institutions, entities, and activities involved in producing, influencing, or delivering a piece of data or a thing. | Adapted from PROV-DM (W3C Recommendation 30 April 2013) |
| rejection | A recorded decision that an admitted object is not accepted for a stated use, with the reason stated; distinct from failure, recall, and supersession. | Project rule |
| failure | Termination of the ability to perform a required function, or performance outside previously specified limits. | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| recall | Withdrawal of a released artifact by its owner, obliging consumers to stop relying on the withdrawn version while the record of it is kept. | Project working use |
| supersession | An owner's replacement of one version by a later one for a stated scope; a composition-specific or application-specific choice is never supersession. | Project rule |
| successor relation | The recorded link from a revised artifact back to the original it revises, with both preserved. | Adapted from PROV-DM (W3C Recommendation 30 April 2013) |
| federation | An arrangement that keeps independently maintained authorities intact and separately governed, so disagreement between them is retained rather than resolved; used here for thesauri, and any extension beyond thesauri is a project analogy that must be labelled as such. | Project analogy |
| thesaurus union | A reconciliation of several source thesauri into one new combined vocabulary, which thereby creates a new authority artifact with its own owner, scope, and version. | Project working use |
| harmonization | Deliberate reconciliation of differing terminologies toward common usage across communities; no source read this pass defines it, so this is the scaffold's working use. | Project working use |
| similarity measure | A computed score of resemblance between terms or texts, usable to prioritize human review and never usable to create semantic authority. | Project working use |
| early merge | Collapsing competing source-scoped meanings, dispositions, or candidate owners into one before adjudication; prohibited in this scaffold. | Project rule |
