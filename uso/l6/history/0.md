# L6 History - Displaced and Historically Significant States

This directory preserves states that are no longer current, and states that are kept because the
record cannot be read without them. Preservation here is a claim about status, not about quality: a
state kept in history may have been correct, and a state still current may later prove wrong. The
work of this directory is to keep the reason for displacement attached to the displaced state, and
to keep the four displacement dispositions and the one retention reason from blurring into a single
idea of "old".

## Manual work

1. Before writing an entry, confirm the state is genuinely displaced. If it is a live alternative
   that one application or composition simply did not select, stop: it stays where it is.
2. Choose exactly one disposition from the table below and name it in the entry. If two seem to
   apply, the underlying event has not been analysed yet.
3. Record the displaced state by exact identity and version, so the state itself remains retrievable.
4. Record the date of displacement, the decision that displaced it, and who made that decision.
5. Record the successor relation where one exists, naming the successor state by exact version;
   where none exists, write that none exists and why.
6. Record the reason in the terms the decision actually used, without improving it in hindsight.
7. Keep any downstream consequence separate from the entry itself: a recall of one state does not
   by itself dispose of every application that used it, and each such application is assessed on
   its own.
8. Leave earlier entries intact. A later reversal is a new entry plus a successor relation, never an
   edit to the old one.

## Displacement dispositions and retention

| Disposition or retention reason | Means | Does not mean | Successor relation | Basis |
|---|---|---|---|---|
| Supersession | A later state has been adjudicated to control in place of this one, for a stated scope | That the earlier state was wrong, or that it is displaced outside that scope | Required: name the superseding state and version | Project rule |
| Rejection | An owner decided not to adopt the state | That the state was tested and failed, or that it was ever current | Optional: name the state adopted instead, if any | Project rule |
| Failure | A check, run, or use did not perform within its stated limits | That the underlying claim is disproved, or that the state was rejected | Optional: name the corrected state or the reopened check | Adapted from ISO/IEC/IEEE 24765:2017(E) |
| Recall | Material already issued is withdrawn from use because a defect was found after issue | Ordinary supersession, or that every downstream use is void | Required: name the defect and the replacement, or state that no replacement exists | Project rule |
| Historical significance (retention reason, not a disposition) | The state is kept because later material cannot be read without it | That it is superseded, rejected, failed, or recalled | Not applicable: record what the state explains | Project rule |

The adapted entry takes only the local sense of the word from ISO/IEC/IEEE 24765:2017(E), Clause
3.1560 'failure', definition 1, printed page 178: "1. termination of the ability of a system to
perform a required function or its inability to perform within previously specified limits; an
externally visible deviation from the system's specification". That standard is a vocabulary; it
says nothing about this scaffold or its layers.

For the successor relation, the local use is narrower than revision in general: compare PROV-O: The
PROV Ontology, W3C Recommendation 30 April 2013, Section 4.2 Expanded Terms, entry
prov:wasRevisionOf: "A revision is a derivation for which the resulting entity is a revised version
of some original. The implication here is that the resulting entity contains substantial content
from the original. Revision is a particular case of derivation."

## Boundary

- Do not retire a live alternative. Non-selection in one application or composition is not
  supersession, rejection, or failure, and produces no entry here.
- Do not collapse dispositions. "Deprecated", "obsolete", and "old" are not dispositions and are not
  used in entries.
- A contradiction, tension, or inconsistency IS a disposition, but it is not a displacement: record
  it where it arose and open an entry here only after an owner adjudicates it into supersession,
  rejection, recall, or failure.
- Do not use this directory as an intake point or as an archive of convenience. New material enters
  at L7 intake.
- Do not delete or rewrite displaced states, and do not remove an entry because it is embarrassing.

When a difficulty here is about the process rather than about a particular displaced state, record
it in /L7/process-lessons.md.
