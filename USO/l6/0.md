# USO/l6/

**Object:** Memory, history, reconstruction, retirement, and query orientation.
**Path:** `USO/l6/` · **Layer:** L6 — LIBRARY · **Owner:** USO/l6/ — the owner of the object's internal memory: prior internal states and versions, branch and decision history, failed paths and unresolved obligations, corrections, supersession, retirement, and retained memory.

L6 is the Library of the bounded scientific object. It answers the Core question "Can the object's internal history, prior states, failures, corrections, and retirement be reconstructed and correctly oriented for inspection?" It holds what the object used to be and how it changed, so that an inspector arriving from L7/ can orient before entering the active payload. It records, preserves, and orients; it does not judge and it does not own external provenance. The Analytic-view table of the specification places L6 with L5 in the upper scientific interior: "Memory/history and research/discourse are the upper scientific interior. They remain separate layer owners even when shown as one research-facing band."

### Owns / represents
- prior internal states and versions
- branch history and decision history
- failed paths and unresolved obligations
- corrections, supersession, retirement, and retained memory

### Permitted actions
- record, preserve, compare, branch, supersede, retire, reconstruct
- retain prior classifications and corrections without erasure
- orient inspection before entering the active payload

### Acceptance / boundary check
- Prior internal states and changes are reconstructable.
- Correction does not require deletion of prior state.
- External source/provenance references resolve back to L7.
- Retirement preserves the record rather than erasing it.

**Boundary / traversal rule.** For an externally encountered object, L7 is the boundary and owns its external provenance/governance relation. L6 is the first interior layer used to reconstruct prior internal states, changes, failures, supersession, and retirement before deeper inspection.

## Git and scientific memory

Git history can support L6 reconstruction, but Git history and scientific memory/provenance are not the same object. Git records repository change events; L6 must preserve the scientific relations, decisions, failures, corrections, versions, and retirement needed for reconstruction. External source, authority, and prior-art provenance remain L7-owned.

The Harmonization Record states the same rule as a disposition: "Supporting-evidence disposition: Git history can support L6 reconstruction, but Git history and scientific memory/provenance are not the same object. External provenance remains L7-owned; internal reconstructable scientific memory remains L6-owned."

Commit identifiers named in an L6 record are orientation pointers to repository change events; the L6 record itself is the scientific memory.

## Direction

Construction enters from `USO/l5/` and leaves toward `L7/`; inspection enters from `L7/` and proceeds toward `USO/l5/`. This follows the two valid directions of the specification — scientific construction outward L0→L1→L2→L3→L4→L5→L6→L7, authorized external inspection inward L7→L6→L5→L4→L3→L2→L1→L0 — with crossing L7 ↔ L6 being a boundary/peering event, not filesystem nesting.
