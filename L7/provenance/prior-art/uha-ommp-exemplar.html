UHA and oMMP on the Layers

Two bounded objects built with this model, filed against it. UHA is a binary codec for a region of space; oMMP is a grammar for recording an observation. They meet at a hard edge: UHA’s own definition refuses to carry an observer, and oMMP cannot proceed without one. That is not a defect in either object, and it is not a coincidence either. It is the boundary the model exists to hold, holding — in two objects that were laid out by it while they were being built.

Provenance

Both of these were built with the model

This is not a page about two systems that happen to fit the Seven-Layer Model. Both objects are the model’s own output — one programme, one method, one lineage — and oMMP goes further: it carries the model inside itself, pinned by hash, as the gate its development has to pass.

That settles what the rest of this page is evidence of. A seam between two independently built systems would be a coincidence worth checking. A seam between two objects built with the same model is the model doing the job it was built for: it kept the observer out of UHA’s L0 while that definition was being written, and it gave oMMP somewhere to put the observer that did not require editing UHA. The fact worth reporting is not that the boundary appears. It is that when it appeared, neither object had to be amended.

The two objects

What each one says it is

Take each object’s own words for its own meaning. That is what L0 is: the semantic contract an object authors for itself, before anything else is said about it.

“A UHA Record is a canonical binary representation of a spatial region … The address is fixed by coordinates alone: two regions sharing a center, extent and epoch encode to the same bytes whether one holds matter and the other vacuum … the record carries no observer, nothing an observer is attached to, and no viewpoint from which the region is seen. The frame field declares an origin and axes, which is a stated convention, not a vantage.”

uha · bz/README.md · Part 1, Definition

“oMMP (Observer MetaModal Platform) — an observer-anchored grammar for recording an observation as typed mathematical fields rather than as a narrative story.”

“The UHA address consumed by oMMP is observer-rooted … The observer’s localized state is foundational address context. oMMP begins its semantic work after that origin is established.”

ommp · README.md; research/definitions/7lm/OBSERVER_ROOTED_UHA_CONSUMPTION_MODEL_2026-07-20.md

Read those together and the edge is plain. UHA declares that no viewpoint is expressed and that there is no field through which one could be. oMMP declares that the observer’s localized state is foundational and must come first. Both statements are each object’s own L0. Neither is wrong. They cannot be merged.

The seam

The wrong fix is to edit UHA

There is an obvious and wrong repair: add an observer field to the UHA record, or reinterpret frame as a vantage. It is wrong for a reason the model states as a rule — higher layers do not silently repair lower layers, and one object never rewrites another object’s authored meaning.

The specification calls the general form of this peering: one object depends on another without owning, copying, redefining, or maintaining the other’s meaning. It records that the case which originated the architecture was Autonomous and Auditonomous sharing one definition. UHA and oMMP are that same case again — and they did not stumble into the same discipline. oMMP holds a copy of the model inside itself as its development gate, pinned by SHA-256, and writes its rule for consuming UHA in the model’s own vocabulary: lower layer, no redefinition. The seam held because the model was in the room while both objects were being built.

Construction outward

UHA, filed layer by layer

The model asks where each kind of claim belongs. UHA is unusually good to file because it has already done the separation itself — its definition, its formulas, its tolerances, its built codec and its sources are distinct documents that govern distinct things.

Two rows deserve attention because they are the discipline working, not just filing. L1 is doing real containment: ruling R1 carries only the exponents, so an inverted, equal, non-positive or overflowing dial has no byte pattern at all. A whole error class is removed from the state space rather than caught downstream. And L3 is honest about its own bound: the README says declaring R_H at the comoving particle horizon “is a causal bound, not a claim that no matter lies beyond it.” That sentence is the L2/L3 boundary observed in the object’s own words — the mathematics is exact, the physical reading is bounded and says so.

L4 · the realized object

Sixty-four bytes, always

The record is where UHA becomes a made thing. Every field below is a lower layer’s contract, carried as bytes — which is what L4 means: resources committed, an identifiable output produced.

The containment rule

UHA does not get re-mapped onto oMMP’s layers

The specification carries a rule for exactly this shape: a whole system with its own internal layers sits inside L4 as a single object. Its internal layer numbering is not the model’s. The rule is written against an OSI network stack; UHA is the same case, closer to home.

A version, not a rival

oMMP is gated on an earlier version of this model

oMMP does not merely illustrate the model — it carries a copy of it and builds against that copy. Its development gate is research/definitions/7lm/seven_layer_methodology.md, “Seven-Layer Methodology v1.3,” pinned by SHA-256. That document is an earlier cut of this model by the same hand; the harmonized specification is where the same line of work arrived. What follows is therefore a version gap inside one lineage, not a disagreement between two.

The kinship is not resemblance; it is descent. v1.3’s stack-wide invariant S1 — “Claims at layer k are derivable solely from artifacts at or below k. No upward layer introduces unproven assumptions about lower layers” — is the harmonized specification’s “claim only what the layer has earned” and “higher layers do not silently repair lower layers,” stated formally. S6, append-only evidence at L4, is the deletion rule. S5, version pinning with “no moving floor,” is the pinned contract. S7 is provenance carried forward. Neither document took these from the other. They are one line of work stated twice — v1.3 as numbered stack-wide invariants, the specification as rules over eight positions — and what moved between them is where a rule sits, not what it says.

What this exemplar establishes

And what it does not

It establishes that the model files two real objects without strain, that the hardest case between them resolves by peering rather than by amendment, and that this is what it looks like when a model is used to build rather than applied to finished work afterward. Neither object had to be argued into position: UHA’s repository already separates definition, formulas, tolerances, codec and sources into distinct governing documents, and oMMP already refuses to redefine a lower layer in so many words. The filing below was transcription, not interpretation. Three things are left to rule.

Open, for ruling

  • v1.3 is a version of this model, and the specification says where a version goes. L7/provenance/prior-art/ is not it: the specification reserves that branch for “external antecedents,” and this is the programme’s own earlier cut, not someone else’s. L6 is it — the layer that must preserve “the scientific relations, decisions, failures, corrections, versions, and retirement needed for reconstruction,” where L8/L6/retired/specification-2026-09-04/ already holds the last superseded text verbatim. Filing v1.3 the same way, with the SHA-256 oMMP pins, would identify the gate oMMP actually builds against and close the lineage. Whether to do it, and under what date, is undecided.
  • oMMP is gated on the older version. Its gate is v1.3 while the harmonized specification is current, and its repository is laid out after autonomous rather than the canonical topology. By v1.3’s own S5 — version pinning, “no moving floor” — a pinned gate is correct behaviour and advancing it is a deliberate act with a date, not housekeeping. The specification already names OMMP among the repositories the topology is available to. When oMMP moves, and whether the layout moves with it, is a ruling.
  • The seam needs a binding of record. The relation drawn above is real in both repositories’ prose but is not filed as a peering object at either desk.
