**Local question:** What identifiable external relation is directed toward the bounded object through a public channel?

## What this directory is

Public ingress represents peering directed from an external counterpart toward the bounded object through a publicly exposed relationship.

[
	ext{external counterpart}ightarrow	ext{bounded object}
]

The incoming object or interaction may be a public comment, issue, request, dataset, definition, response, artifact, service result, or another distinguishable representation.

Ingress describes direction. Public describes exposure. Neither coordinate establishes acceptance, ownership, authorship, validity, or internal scientific use.

## Why it exists

A bounded object may receive externally directed interactions in a way that is itself publicly observable. This position makes that external relation addressable without confusing public visibility with scientific standing.

## Holds

- `peer-N/` positions for external counterparts using this channel;
- `object-M/` positions for distinguished incoming objects or interactions;
- the combined coordinates **public + ingress**.

## Does not hold

- public outbound relations — `L7/peering/public/egress/`;
- restricted inbound relations — `L7/peering/private/ingress/`;
- the proposition that all public sources are peers;
- acceptance, provenance, governance, or scientific interpretation merely because something arrived publicly.

## Boundary / traversal rule

Public receipt is still only a surface relation. Scientific use, semantic adoption, evaluation, or retention are separate representations if they occur.

## Exemplar

An external researcher opens a public issue identifying a possible error. The issue is public ingress. The correctness of the report is not decided by its peering position.

## Standing

- This branch may remain empty.
- Public ingress is not a universal route for external information; it applies when a public peer relationship is what is being represented.
